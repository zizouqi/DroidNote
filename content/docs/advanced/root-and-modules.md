解锁 Bootloader（BL）与获取 Root 权限可以带来极高的系统控制力，但也伴随着显著的代价与维护成本。

## 解锁与 Root 前必须评估的代价

- **数据清空**：大多数厂商解锁 Bootloader 会立即触发恢复出厂设置，必须提前完成全量外部备份。
- **风控与认证影响**：TEE 状态与 Play Integrity / 银行类 / 政务类 / 部分游戏反作弊可能会检测 BL 状态、Root 痕迹或异常环境。
- **保修与更新约束**：部分厂商解锁后不再享受官方常规保修或无法直接应用增量 OTA。

## 主流方案定位参考

- **Magisk**：用户态通用方案，生态最广，依赖修补 `boot` / `init_boot` 与 Zygisk 模块加载。
- **KernelSU / APatch**：基于内核态的权限管理思路，隐藏性与细粒度控制能力各有特点，但对内核版本或驱动兼容性有明确要求。
- **LSPosed**：在启用 Zygisk 的前提下为指定应用注入 Xposed 模块；遵循 **按需勾选作用域** 原则，不要将无关系统进程加入模块作用域。

严禁安装来源不明、闭源且要求全局 Root / 全系统注入的模块。任何模块更新前先确认与当前 Android 大版本及管理器版本兼容，并保留安全模式或救砖用的官方 `boot` / `init_boot` 镜像。
